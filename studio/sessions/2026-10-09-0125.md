### What changed
- **Schema:** `buildings.json` `attack` (the unit attack object; value ≥ 1, range > 0, an aimed projectile, `targets` not
  `buildings`) and `detector` (m, ≤ `MaxSight`; stored for M4-5). Both towers ship `{10 pierce, cooldown 2 s, range 18,
  windup 0.4, bolt / arrow, units}` + `detector 16`. `ContentHash` covers both; golden `data-hash` moved once, every `k` line equal.
- **Towers:** a finished building with an attack scans every 4 ticks (staggered) through the spatial hash by the unit priority,
  never a building, only what its owner sees (`VisionSystem.BuildingSeesUnit`: the building as viewer, high-ground rule and lip),
  fires a led aimed projectile from its footprint centre (`ProjectileStore.AttackerIsBuilding`). A site never shoots. Ranged
  Weapons reaches towers (docs/02 says "pierce units and towers": `TechState.MatchesBuilding`). A tower's hit sets no
  `LastAttacker`, starts no retaliation and reveals nothing from high ground (BUG-0270). Tower state hashed (bit 31 of the
  production word; a building that never shot hashes as before).
- **Ghost list:** `Fog.Ghosts(player)` one `BuildingGhost` per building slot (generation, type, anchor, owner), set / refreshed
  when any footprint cell is visible, kept unseen (also after the building is gone), dropped the first update the remembered
  footprint is in sight with the building gone. Hashed only while some player has an entry. An explicit Attack on a
  remembered-but-unseen building is accepted (`HeldByGhost` / `Blind` / `GoneButRemembered`): the unit walks there, swings only
  once it sees it, and the order ends when the ground is seen with the building gone.
- **Placement:** `CanPlace` → `Unexplored` (value 10) after the terrain rules and before units in the way, when any footprint
  cell is unexplored. Many test scenes now start explored (`TestSim.Explored`, a seam over `FogStore.ExploreAllForTests`).
