### What changed
- `World.CanPlace(player, typeId, anchorCell, out PlacementError)`: public, read-only, allocation-free, the one
  rule `Build` applies; reasons in order UnknownType, WrongFaction (`World.FactionOf` = player mod factions until
  the M6 lobby), OffMap, Blocked, SealsGround, UnitInTheWay (enemy or own holding unit), CannotAfford, StoreFull.
- Never-seal rule `Map/SealCheck` (ring test, then a multi-source labelled flood on borrowed flow-field scratch):
  a footprint may be taken only if every two passable cells that connect now still connect. Dev `SpawnBuilding`
  obeys it too. Closes BUG-0078 for placements; a Cancel / destruction of an enclosed building can still leave a
  pocket (documented in docs/03; BUG-0093).
- `Command.Build` (kind 8, worker unit order, Shift-queueable with `UnitStore.QueueTypeId`): pays and places a
  site (own non-holding units in the footprint are set down on the nearest free ring cell, ties to the lower cell,
  8 rings then `NearestPassable`) or joins the own site of that type at that anchor. `ConstructionSystem.Run`
  (phase 4 after gathering): `WorkNeeded = 3 x buildTicks`, n builders in reach add n + 2 a tick (docs/02
  `t x 3 / (n + 2)` exactly); site hp = max(1, maxHp x work / needed); completion at full hp idles the builders.
- `Command.Cancel` (kind 9, not a unit order): floor refund of the unbuilt fraction, builders idle, opening change.
  `Command.Repair` (kind 10): `rules.json` `repair.rateFactor` 0.5 / `costFactor` 0.25 through 2^16 fixed-point
  accumulators (hashed); stops when a payment would go below 0 or the player has 0 of a costed resource.
  `BuildingStore.Damage` seam frees at 0 hp (opening change; combat uses it in M4).
- Hash: building `UnderConstruction` / `Work` / repair accumulators, unit `BuildTarget`, queued Build type id in the
  high half of the kind word (units without the new fields hash as before). Replay format stays 3; golden
  regenerated for `data-hash` + checksum only (Producer verified the diff). BUG-0079 item 1 (missing `cost` is one
  error) and the BUG-0090 `BuildingSlot.cs` comment folded in. docs/03 "Implementation (M3-3)", docs/01 row.

### Decisions and surprises
- **BUG-0078 marked fixed with BUG-0093 carrying the residual** (Producer): the brief defined the close as "no
  placement seals ground", which holds against an independent oracle. The pocket a Cancel leaves is a different
  mechanism (a reopened enclosed footprint) and gets its own fix in the sim hardening session (next session):
  either mark reopened cells that reach no other region as a pocket (as the nav grid does at load, but reopened
  when a neighbour opens) or make exposure mean "reachable"; the hardening brief chooses.
- Never-seal preserves *existing* connectivity rather than whole-map connectivity, so it works after a pocket
  exists; documented in docs/03.
- The seal flood borrows `FlowFieldCache.BuildScratch` (the dev's own arrays broke QA's 1024-map 228 MB guard);
  `CanPlace` is read-only with respect to sim state but writes that scratch: fine on the sim thread between ticks,
  which is how the view runs. The ghost-preview brief will say so.
