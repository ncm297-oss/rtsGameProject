## Findings
- [S3] BUG-0039: 128 units to 64 neighbouring goals: the pack rule and the 22% give-up bound hold on one map only. Repro: `SeedSweepQaTests` reports. On new-seed maps 1-40, 25/40 break the pack rule and 22/40 exceed 22% (worst 47/128). On the old maps (`PreMix(1..20)`) it is 12/20 and 5/20, so this predates M1-6. The dev reported 26/40 and 10/40; with the test's own bound QA measures 22/40. The 2,500 units to 4 points row arrives 822/2500 (32.9%, matching the dev), 946 and 739 on the next two seeds.
- [S4] BUG-0040: Two replay issues. (1) `ticks` and `checkpoint-interval` have no format limit: a resealed header with 2^31-1 for both reads as `None`, and `Run` would spin for hours. (2) Latent for M5: the phase-14 checkpoint hashes pending commands, so commands enqueued during a tick (the AI, per the `Enqueue` docs) can't match playback, which feeds every command between ticks.

Judgement on `TestSeeds.PreMix`: it is sound, and it hides no regression from this change, because M1-6 does not touch movement and the pinned tests run on exactly their old streams. It does keep single-map calibrations alive, and BUG-0039 records that.

Notes (not bugs): `SimInfo.Version` is not checked on playback (documented). The data hash covers display text, so any data text edit forces a golden regeneration (documented). Renaming a faction folder alone fails to load (folder and id must match). A consistent rename changes the key and the hash, which is correct because the key is data and folder order sets faction ids. A crafted file may declare 1,000,000 units on a 1024 map, which is within the format limits.
