## Findings
- [S4] BUG-0960: M6-S2 save nits. Three items:
  - A forged header with every capacity at 1,000,000 makes `TryLoad` allocate about 1.4 GB (420 ms) before it refuses `Malformed`. An OutOfMemoryException on a smaller machine would escape the "never throws" promise.
  - 81 of 47,714 forged small saves that load throw within 3 ticks (`FlowFieldCache.Get`, `FogStore.Combine`). docs/03 already says forged files can misbehave.
  - The save Perf row failed once with two suites running.
  - Repro: `dotnet test sim/Rts.Sim.Tests --filter FullyQualifiedName~SaveForgeryQaTests`.
- Notes, not bugs:
  - The SealCheck memo really is harmless. 945,000 `CanPlace` reads on the reference only (50,191 floods, 0 on the load) left the two hash-equal for 2,100 ticks. `Flood` reads only `Blocked`, and every `Blocked` change bumps `NavGrid.Version`; the pocket path leaves `Blocked` unchanged.
  - Saves embedded after other bytes in a stream load from the stream's position. A save followed by more bytes is `Malformed`, as documented. Reading the same stream object twice gives `Truncated`. Non-seekable streams with short reads load fine.
  - The menu-match scene used by the Perf row has only 39 units at tick 12,000. Size and time come mostly from fixed-capacity arrays and the 128 flow fields, so a busier match should not change them much.
  - Housekeeping in `studio/qa/coverage.md`: removed a stale duplicate "Menus, save/load, export" row, an older copy of the row above it.
