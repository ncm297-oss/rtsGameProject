## Acceptance criteria (independently verified)
1. EntityHandle / UnitStore — VERIFIED — `readonly record struct EntityHandle(int Index, int Generation)`. Free bumps the generation and the stale handle stays dead after reuse (capacity-1 alloc/free/alloc, plus 1M random cycles on capacity 64 with stale-handle sweeps every 1,024 cycles). Forged handles (index -1, Capacity, int.MinValue/MaxValue, wrong generation, never-allocated) never resolve, and Free on them throws. Double free throws. Capacity comes from `SimConfig.UnitCapacity`. Alloc at capacity throws `InvalidOperationException` and TryAlloc returns false. Capacity 0 or -1 throws.
2. SimRng — VERIFIED — Seeds 0, -1, int.MinValue, int.MaxValue and long.MinValue each give more than 9,990 distinct values in 10k draws, at most one zero, and nonzero state. Interleaved draws on two streams equal the same streams drawn alone. NextInt edge ranges (int.MinValue..+1, MaxValue-1..MaxValue, -5..5, 0..3) stay in bounds over 100k draws and hit both ends. A 7-bucket chi check is within ±1.5%. NextFloat over 1M draws stays in [0,1), and the maximum possible output is below 1.
3. SimMath — VERIFIED (inside the stated bounds) — Source scan is clean. Over a 401x401 Atan2 grid, max error is <=1e-3 (dev claims ~1.2e-5, consistent). Signed zeros and axes stay in [-pi, pi]. The Sin/Cos -> Atan2 round trip is within 1e-3. On [-1000, 1000] rad the Sin error is <=1e-3. NaN and Infinity inputs don't throw. Repeated calls are bit-identical (the dev test re-checked). Outside the criterion: |x| >= ~1e8 returns values far outside [-1, 1] (BUG-0003).

## Findings
- [S3] BUG-0003: SimMath.Sin/Cos return values far outside [-1, 1] for huge angles — `SimMath.Sin(1e9f)` = 3.1e10; `Sin(1e20f)` and `Sin(float.MaxValue)` = -Infinity.
- [S3] BUG-0004: A rejected Enqueue (queue full) still advances the player's sequence counter — CommandCapacity 2, enqueue 3: the third throws, but StateHash changes.
- [S3] BUG-0005: CommandQueue insertion sort is O(n^2) — 8 players round-robin: 1k cmds 1.2 ms, 2k 4.8 ms, 10k 107 ms (Release) in one tick.
- [S4] BUG-0006: SpawnUnit accepts NaN/Infinity positions into sim state — spawn at (NaN, +Inf) gives slot 0 position `<NaN, ∞>`.
- Note (no bug): `Atan2(-0f, -1f)` returns +pi where Math gives -pi. It's the same direction and within range, so it's acceptable.
- Note (no bug): `UnitStore` arrays and `World.Rng()` are publicly writable, so "read, never write" is a convention only. QA tests rely on this to flip bits.
- Note (no bug): `UnitStore.FreeListAt(i)` has no `i < FreeCount` check and can read stale entries past the live free list.

## Stress results
- Handle churn: 1M random alloc/free on capacity 64 found no stale resolve, no slot handed out twice, and every sampled double free rejected. Free-list and handle hash are identical across two 1M-cycle runs, and seed 77 differs from 78. 1M alloc/free cycles on a single slot gave strictly increasing generations.
- Determinism: a 2,000-tick fuzz (4 players, 0-5 random Noop/Spawn commands per tick, Combat/AI RNG draws each tick) repeated 20x was identical at every 100-tick checkpoint. 40 seeds x 2 runs x 1,000 ticks were all reproducible and all distinct.
- Flood: 10k commands in one tick allocate 0 bytes. Sort+apply time (Release, worst of 3): 500 = 0.4 ms, 1,000 = 1.2 ms, 2,000 = 4.8 ms, 10,000 = 107 ms (Debug 175 ms).
- Scale (empty tick, Release): 500 units 2.5 us/tick, 1,000 units 4.8 us, 2,500 units 5.8 us. StateHash: 0.18 / 0.48 / 0.53 ms. Far under the 4 ms average budget.
- Architecture guard negative test (scratch clone): a sim file with `using static System.MathF; Tan(x) + System.MathF.Acos(x) + Sin(x)` fails `SimSource_UsesNoForbiddenApis` on both lines.
