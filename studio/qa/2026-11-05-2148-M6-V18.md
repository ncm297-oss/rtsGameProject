## Findings
- [S3] BUG-1092: `--players` capped to a map file's starts can leave every player on one team, so the match never ends. Repro: `--players 4 --map raraku --team 1 1 --team 2 1 --team 3 2` gives 2 players, both on team 1, and `IsEnemy(0, 1)` is false. BUG-1066's one-team check runs in `LaunchOptions.Parse` before `Match` caps the players. Only the command line reaches it; the setup refuses the same case (Start disabled, `setup.one_team` shown). `QaM6V18bTest` row `KNOWN BUG-1092` fails only with `-- --strict`.
- [S3] BUG-1093: `TeamsTest` failed one full scene loop on a GodotSharp "Handle is not initialized" error inside `GD.Load` (`Main.StartMatch`), even though it printed PASS and exited 0. It passed 5 / 5 alone and isn't in this change's code; filed so the flake is tracked.
- Notes (not bugs):
  - While a map is picked, the greyed Forests / Gold mines still show the generator's 12 / 8 although Raraku has 6 forests and 12 mines. The brief says the values are kept and unused, so this is as specified. The owner may find it misleading; a later polish could blank them or show the map's counts.
  - `--map-size` on a map file is ignored without a warning (the docs say "ignored"; the dev reported this too). `--players` gets a warning; `--map-size` / `--forests` / `--mines` don't.
  - The greyed Map size list is still a Tab stop (a disabled OptionButton keeps its focus mode). Down, Up, Enter, Space, KP Enter, Left and Right on it change nothing and open no popup, so the keyboard can't edit it.
  - `ReplayStore.IsMapToken` accepts any non-space token (a tab, a path). Such an id shows raw in Load Game and Watch refuses it (`InvalidHeader`, unknown map). This is harmless.

Id-shaped unknowns (no_such_map, 1, _, 64 × a, raraku_) are parsed, then `MapFor` gives generated. The 64-character bound holds. The last good value wins (`raraku` then `Junk` gives raraku; `raraku` then `no_such_map` gives generated).
