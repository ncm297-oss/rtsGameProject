## Findings
- [S3] BUG-0025: With live goals > cache slots, eviction picks the lowest goal cell touched this tick, not the newest order. Older groups stall while newer ones walk, and every build is churn. Repro: un-skip `QA/FieldBuildFairnessQaTests.LiveGoalsOneOverCapacity_OlderOrdersNeverWaitWhileNewerWalk_NoEndlessChurn` (34 goals on 32 slots: 200 builds in 100 ticks; older groups waited 200 group-ticks, newer 0).
- [S4] BUG-0026: Same-tick order bursts: the player whose goals have low cell indexes starts sooner, by up to 3.7 ticks on average (14.67 vs 10.95 at batch 8). This is within the documented ceil(N/2) bound but tied to map side. Repro: `Fairness_TwoBases_... (simultaneous: True)` output.
- [S4] (no file) A 1024x1024 World now allocates 225.9 MB, vs 221 MB in M1-4b. The +4.2 MB is the dev's cell-to-slot index (documented in docs/03). Capacity stays 32 as required. This is above the "must not exceed ~221 MB" in the QA focus by 2%, so it's the Producer's call. Pinned at < 228 MB by `World_1024Map_CacheStays32_MemoryBounded`.
- Watch item (no bug): `NavGrid.Version` is not hashed. That is fine while the grid is immutable. When passability can change (M3+), the grid state must join the hash, or a version bump alone changes behavior without changing the hash.

Dev deviation (cell-to-slot index): it can't drift out of sync with the slots, and it is derived from them. `IndexFuzz_...` checks index == inverse of the slots after each of 3,000 random Get/TryGetCached/version-bump ops at capacity 1/2/3/32 (blocked target cells included). `Contains` matches a brute-force scan on every op. The 50-seed fuzz checks the index on every tick. Mutation: not clearing the evicted cell is caught by 12 tests.

Dev-drafted QA test rewrites (QA owns them and accepts all three): the pre-warm test now asserts that a pre-warm changes the hash and that identical pre-warms stay equal, which matches the BUG-0021 decision. The 64-group test's 34-tick window = 1 command tick + ceil(64/2) build ticks + 1 spare, guarded by an assert on the cap; 0 of 960 group-windows frozen (was 483). The MovementStressTests churn test now churns both runs identically and asserts that a run without churn differs. All are correct under the decision; none loosens a passing check.
