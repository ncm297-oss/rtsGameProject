## Findings
- [S3] BUG-0480: an `onDeath` passive that applies `stealthed` reaches 1 of 5 listed friends. `PassiveSystem.OnDeath` loops over its neighbour list in `World.ShoveNeighbors`. The first friend's new stealth runs `StealthSystem.OnStealthStarted`, which writes its enemy query into that same array. Repro: `QA/StealthQaTests.AnOnDeathPassiveApplyingStealthed_ReachesEveryListedFriend(true)` (skipped, fails 1 vs 5; the Frenzied control row passes).
- [S3] BUG-0481: shipped data minus the `revealed` entry loads clean, and attacks and casts from stealth then never reveal (`RevealedStatus` -1). Repro: `QA/StealthQaTests.StealthedWithoutARevealedStatus_IsRefusedAtLoad` (skipped).
- [S4] BUG-0482: a stealthed attacker that already carries 8 statuses is never Revealed (the reveal is dropped as a ninth status). Repro: `QA/StealthQaTests.AStealthedAttackerWithAFullStatusStore_IsStillRevealed` (skipped; confirmed failing without the skip).
- Note (not a bug): an explicit Attack applied in phase 1 against a unit that was visible (its Revealed still live) is accepted. If the Revealed ends in that tick's phase 5, the chaser holds a hidden target until its next scan drops it. This is the BUG-0150 lost-from-sight rule as briefed; it happened twice in seed 12, and the fuzz asserts the drop within two scans.
- Note: the dev report's memory delta (+17,424) used the pre-merge handoff baseline; the true delta on this branch is +9,144 B.
